# 抗滥用（限速 / 并发上限 / 反射防护）

## Goal

让 rstun 可以**公网裸跑**：把「伪造源 + 反射放大」与「资源耗尽」两类风险降到可接受。

## 需求

1. **每源 IP 令牌桶**（UDP 与 TCP 共用）：默认阈值需能支撑家用 NAT 后多设备（≥ 100 req/s/IP），可配置。
2. **全局并发上限**：在途请求数上限（Semaphore），超限时 UDP 静默丢弃、TCP 关闭连接，并计入统计。
3. **反射放大防护**：
   - `RESPONSE-PORT` / `CHANGE-REQUEST` 只在请求 ≥ 最小尺寸（如 40 字节）时处理，否则 400；
   - 这类请求与普通请求共用同一限速桶；
   - 响应字节数 ≤ 请求字节数 × 1.0（鉴权错误响应除外，需单独说明）。
4. **名单**：可选 `--deny <CIDR>` / `--allow <CIDR>`（默认空）。
5. **可观测**：被限速/被拒绝的计数进入 metrics 与退出统计。
6. 默认**全部关闭**（保持现有行为），通过 `--rate-limit` 等开关启用。

## 非目标

- 不实现基于内容的 DPI、不封禁协议模式。
- 不做跨实例共享限速（单机状态即可）。

## 验收

- [ ] 压测：单源 IP 超阈值后请求被丢弃，未超阈值的源不受影响
- [ ] 伪造源 + `RESPONSE-PORT`：放大比 ≤ 1，且命中限速（日志/指标可见）
- [ ] 并发上限：TCP 洪水下内存/描述符稳定，进程不退出
- [ ] 默认关闭时：字节级冻结测试仍通过

## 风险

| R | 缓解 |
| --- | --- |
| NAT 后误伤 | 默认阈值宽松 + 可按网段 allow |
| 限速表本身的内存放大 | 哈希表 + LRU 上限，定期清理 |
