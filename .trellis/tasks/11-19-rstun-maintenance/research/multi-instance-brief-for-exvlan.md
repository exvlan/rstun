# 多实例能力评估材料（给 EXVlan 的网络/运维）

> 用途：在发布 `26.410.108` 之前，先确认你们的网络形态能否满足多实例的**硬前提**。
> 上游仓库：`exvlan/rstun`（`main` 已合入，**尚未发版**）。
> 参考清单：`contrib/k8s/multi-instance.yaml`（两节点 hostNetwork + 同一 VIP/各自 IP）。

## 1. 能力是什么

N 个 rstun 实例在**不要求 5 元组粘性**的负载均衡后，仍能正确服务 TURN：

- 同一客户端 5 元组在任意实例上都被路由到**唯一归属实例**（确定性哈希，静态成员表）；
- `Refresh` / `CreatePermission` / `ChannelBind` / `Send` / `ChannelData` 在非归属实例上自动转发；
- TCP/TLS/DTLS 控制连接断开会**立即**释放归属实例上的 allocation（不等 TTL）；
- RFC 6062（`--turn-tcp-relay`）的出站与被动模式都跨实例可用。

**默认关闭**：不写 `--cluster-*` 时行为与现在的 `26.410.107` 完全一致（我们逐字节比对过）。

## 2. 硬前提（不满足就不要上多实例）

### 2.1 回程源地址必须稳定（最重要）

客户端（尤其 WebRTC 的 connected UDP socket）只接受来自「它发送目标地址」的响应。
而 peer→client 的数据由**归属实例**直接发出。所以你们的网络必须满足其一：

| 形态 | 说明 | 你们是否具备 |
| --- | --- | --- |
| A. 每实例独立公网 IP | 客户端 DNS 拿到其中一个，直连该 IP | ? |
| B. 共享 VIP + DSR | 回程绕过 LB、源地址仍是 VIP（需 VIP 配在每个后端） | ? |
| C. NAT 型 LB | 回程经 LB 转换，客户端看到的一直是 VIP | ? |
| D. 纯 L4 轮询/哈希 LB，且回程不经 LB | ✗ 不支持：客户端会丢弃 | — |

### 2.2 端口与地址

- 每个实例 `--listen` / `--turn-tls-listen` / `--turn-dtls-listen` 必须用**相同端口、不同 IP**（靠 IP/netns/节点区分，不能靠端口区分）。
- UDP relay 段可以共用（后绑的实例会自动跳过被占端口）。
- 若启用 RFC 6062：TCP relay 段**必须每实例一段且不重叠**（`--tcp-relay-ports`，缺失会拒绝启动）。
- 集群内部端口（示例 `34970`）需在成员之间互通；公网或通配地址必须配 `--cluster-secret`。

### 2.3 成员表

- 每个实例都要配置**完全相同**的 `--cluster-peer <id>@<ip:port>` 列表（启动时用摘要比对，不一致直接拒绝启动）。
- 改成员 = **排空重建**：成员变化会让部分键换主，在途 allocation 在 LIFETIME 到期前不可用。不支持在线迁移。
- 配额/限速/`--max-inflight` 仍**按实例计**，全局上限 = N × 单实例，需要在容量规划里算进去。

## 3. 需要你们确认的问题

1. 现在客户端是怎么找到 TURN 地址的？（DNS 多 A / 固定 VIP / 单一 IP）
2. 负载均衡是哪一层、什么模式？（L4 轮询 / 哈希 / NAT / DSR；或根本没有 LB，单机直连）
3. 能否给两实例分配**不同 IP、相同端口**，且回程源地址稳定（A/B/C 任一）？
4. 有没有真实的多实例需求（当前单实例是否已经不够：CPU / 带宽 / 单点故障）？
5. 是否需要 RFC 6062？如果需要，能否为每个实例划独立 TCP relay 段？

## 4. 我们能提供的

- `contrib/k8s/multi-instance.yaml`：两节点 hostNetwork 的参考清单；
- `docs/book/src/turn.md` 的「多实例」章节（拓扑、端口、前提、限制）；
- 发布后（`26.410.108`）可直接 `--cluster-*` 试用；不启用则完全无感。

## 5. 建议的推进顺序

1. 你们先回答 §3，我们判断形态是否落在 A/B/C 之内；
2. 若在，先在**测试环境**起两实例 + 你们的 LB，跑一遍我们的验收脚本（UDP/TCP/TLS/DTLS 各一条，含跨实例）；
3. 验收通过再发版并给升级说明（沿用 `.105 → .107` 那份的格式）。

> 如果 §3 的答案是「单一 VIP + 纯轮询 LB，回程不经 LB」，那**不建议上多实例** ——
> 这不是实现能绕过的限制，是 TURN 协议对源地址的要求。
