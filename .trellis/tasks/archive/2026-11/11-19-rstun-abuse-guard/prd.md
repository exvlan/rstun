# 抗滥用（限速 / 并发上限 / 反射防护）

## Goal

让 rstun 可以**公网裸跑**：把「伪造源 + 反射放大」与「资源耗尽」两类风险降到可接受。

## 需求

1. **每源 IP 令牌桶**（UDP 与 TCP 共用）：默认阈值需能支撑家用 NAT 后多设备（≥ 100 req/s/IP），可配置。
2. **全局并发上限**：在途请求数上限（Semaphore），超限时 UDP 静默丢弃、TCP 关闭连接，并计入统计。
3. **反射放大防护**：
   - 管辖范围：**UDP** 且**确实能重定向**的请求 —— `RESPONSE-PORT` 总是；`CHANGE-REQUEST`
     仅在 `--alt-listen` 给了第二个地址时（无 plan 时它挪不动任何东西，不拦）；
   - `--reflect-min-request` 默认 **20**（= STUN 头长，只挡「不成帧」的输入；能携带
     `RESPONSE-PORT` 的最小请求是 28 字节，门槛取 40 会挡掉全部真实 RFC 5780 探针）；
   - 允许值 = `max(请求字节数 × ratio, 请求字节数 + 32)`，默认 ratio **2.0**；
     32 = 重定向响应必带的固定属性（`XOR-MAPPED-ADDRESS` 12 + `--alt-listen` 的
     `RESPONSE-ORIGIN`/`OTHER-ADDRESS` 24）；小请求（< 40 字节、且在管辖范围内）的成功响应
     省略**可选**的 `SOFTWARE`，把放大压到固有下限：带 alt-listen **2.00×**（28 → 56），
     无 alt-listen **1.14×**（28 → 32）；
   - 这类请求与普通请求共用同一限速桶；拒绝时回 400（40 字节），若 400 本身超过
     `请求 × ratio`（严格，不含 32 字节余量）则静默丢弃 —— 拒绝本身不许放大。
4. **名单**：可选 `--deny <CIDR>` / `--allow <CIDR>`（默认空）。
5. **可观测**：被限速/被拒绝的计数进入 metrics 与退出统计。
6. 默认**全部关闭**（保持现有行为），通过 `--rate-limit` 等开关启用。

## 非目标

- 不实现基于内容的 DPI、不封禁协议模式。
- 不做跨实例共享限速（单机状态即可）。

## 验收

- [ ] 压测：单源 IP 超阈值后请求被丢弃，未超阈值的源不受影响
- [ ] 伪造源 + `RESPONSE-PORT`：响应 ≤ `max(请求×ratio, 请求+32)`（默认 2.0/32；
      带 alt-listen 的固有下限 2.00×、无 alt-listen 1.14×，见 README 实测表），
      且 `reflect_rejected` / `dropped` 计数可见
- [ ] 防护真的能拒：`--alt-listen` 下 40 字节「`CHANGE-REQUEST` + `PADDING 8`」→ 400，
      重定向目标地址 0 个包
- [ ] 并发上限：TCP 洪水下内存/描述符稳定，进程不退出
- [ ] 默认关闭时：字节级冻结测试仍通过

## 风险

| R | 缓解 |
| --- | --- |
| NAT 后误伤 | 默认阈值宽松 + 可按网段 allow |
| 限速表本身的内存放大 | 哈希表 + LRU 上限，定期清理 |
