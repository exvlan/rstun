# 性能基线重测（26.410.103）

## 背景

`docs/perf.md` 的基线是 **2026-11-20 / `rstun 26.410.100`**，之后发生：

- 依赖升级到 `digest 0.11` 一代（hmac 0.13、sha1/sha2/md-5 0.11）；
- `clap 4.6.9`；
- `libc` 提升为 unix 直接依赖（DONT-FRAGMENT），依赖面 **9/13 → 10/14**；
- RAF / DF / IPv6 relay 等 TURN 能力（默认路径未变，但代码体积变了）。

文档里 §3/§4 标题仍写「9 个直接依赖 / 13 个直接依赖」。用户已确认**全面重测并更新**。

## Goal

用 `script/lab/rstun-load.sh` 在**同一环境**重测 `26.410.103`，把 `docs/perf.md` 更新为
当前版本与依赖面（10/14），并保留可复现命令与「参考基线、非门禁」的口径。

## 范围

- 重测 lean 与 `--features full` 两组：§3/§4（吞吐、延迟、体积）、§5（限速对照）、§6（容量随负载）；
- 更新 §1 环境（CPU/内存/内核/编译器版本/日期）、被测版本串（`26.410.103+<sha6>`）；
- §0 结论里引用新数字；§7/§8（本地门禁、局限）保持，必要时补「本次测量与前次的差异原因」；
- 明确记录：**数值随机器与负载变化**，只用于同机前后对比。

## 非目标

- 不改 CI 阈值（`qa-scheduled.yml` 只上传数值，仍不设硬门禁）；
- 不做函数级基准（bin-only crate，维持黑盒口径）；
- 不改服务代码、不发版。

## 约束

- 测量期间避免并行重负载（cargo build / 其它 lab 同时跑会污染数据）；
- 命令必须与文档现有 §2 一致（可照抄复现）；
- 若某项无法复现（端口占用/权限），记录并在文档里说明，不静默换口径。

## 验收

- [ ] `docs/perf.md` 的版本、日期、依赖数（10/14）、体积与实际一致
- [ ] §3/§4 表格数字来自本次实测，且命令可照抄
- [ ] §0 结论不与表格矛盾
- [ ] `script/ci/check-docs.sh` 通过
- [ ] 变更只涉及 `docs/perf.md`（如需脚本微调，单独说明）
